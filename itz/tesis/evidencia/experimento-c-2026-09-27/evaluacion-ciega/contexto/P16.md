# PT-05 — Dockerfiles de producción y CI/CD a Cloud Run

_BASE: Esqueleto del aplicativo_

Deja el aplicativo desplegable: Dockerfiles de producción multi-stage para los dos servicios de Cloud Run, nginx.conf del frontend y los workflows de GitHub Actions para PR y para el despliegue desde main.

## Entregables

- apps/backend/Dockerfile (producción): build node:20-alpine (npm ci, prisma generate, nest build) y runtime node:20-alpine con dependencias de producción, dist y prisma; usuario no root; PORT=8080; CMD npx prisma migrate deploy && node dist/main.js
- apps/frontend/Dockerfile (producción): build node:20-alpine (npm ci, vite build con ARG VITE_API_BASE_URL) y runtime nginx:1.27-alpine sirviendo dist en $PORT=8080
- apps/frontend/nginx.conf: fallback SPA, GET /healthz y escucha en $PORT mediante una plantilla envsubst
- Archivo .github/workflows/ci.yml en cada PR, con filtros por app afectada: lint, typecheck, Jest con un servicio postgres para los e2e, prisma validate, Vitest y build de las dos imágenes Docker de producción
- Archivo .github/workflows/deploy.yml en main: autenticación con Workload Identity Federation, build y push a Artifact Registry con el tag del SHA y gcloud run deploy de itz-agenda-api (Cloud SQL, secretos de Secret Manager, probes a /api/health) y de itz-agenda-web (probe a /healthz)
- docs/despliegue.md o una sección en el README de la raíz con las variables, secretos y recursos GCP necesarios (Cloud SQL, Secret Manager, Artifact Registry, Load Balancer /api → backend)
