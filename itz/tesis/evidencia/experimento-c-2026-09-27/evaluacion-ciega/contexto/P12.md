# PT-02 — Base del backend NestJS: configuración, Prisma, Swagger y health

_BASE: Esqueleto del aplicativo_

Scaffolding de apps/backend según la arquitectura: módulos vacíos, configuración validada, PrismaModule con el esquema y la migración inicial del modelo de datos, manejo uniforme de errores, Swagger en /api/docs y el healthcheck. También crea el README del backend. Sin endpoints de negocio.

## Entregables

- Proyecto NestJS con nest-cli.json (plugin de @nestjs/swagger activado), tsconfig y scripts: start:dev, build, test, test:e2e, lint, typecheck
- src/main.ts: prefijo global /api con versión v1, ValidationPipe global (whitelist, transform), cookie-parser y enableShutdownHooks
- src/config/: esquema de variables de entorno validado con zod y ConfigModule global
- src/prisma/: PrismaModule y PrismaService
- prisma/schema.prisma con Usuario, Cliente, TokenUnUso, Sesion, DocumentoLegal, AceptacionLegal y EventoAuditoria, sus enums e índices únicos (correoNormalizado, tokenHash, refreshTokenHash e índices parciales de Cliente mediante SQL en la migración); migración inicial versionada
- prisma/seed.ts idempotente: usuario ADMIN desde variables de entorno y documentos legales vigentes de ejemplo
- src/common/: ErrorDto {codigo, mensaje, campos?}, filtro global de excepciones que mapea errores de validación y de negocio a ErrorDto, clase base BusinessException con código estable
- Swagger (OpenAPI 3) en /api/docs con la especificación en /api/docs-json, esquema bearer configurado y ErrorDto registrado
- Módulo health: GET /api/health (liveness y ping a la BD), excluido de Swagger y de /v1
- Carpetas de módulos vacías según la estructura (auth, registro, password-recovery, usuarios, clientes, tokens, notificaciones, legal, auditoria), sin lógica
- Jest configurado con un spec unitario de ejemplo y un e2e con supertest de /api/health contra la BD de pruebas
- apps/backend/README.md: qué hace, cómo levantarlo solo y con compose, variables de entorno, migraciones y seed, cómo correr las pruebas unitarias y e2e, estructura de carpetas y la URL de Swagger (http://localhost:3000/api/docs)
- Actualización del README de la raíz con los comandos de migración y seed dentro del contenedor
