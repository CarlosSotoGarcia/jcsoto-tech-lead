# PT-01 — Entorno de desarrollo dockerizado del monorepo

_BASE: Esqueleto del aplicativo_

Crea el monorepo con workspaces de npm (apps/backend, apps/frontend) y deja todo el entorno de desarrollo en contenedores: un docker-compose.yml en la raíz con postgres, mailpit, api y web; un Dockerfile.dev por app con el código montado como volumen y recarga en caliente (nest start --watch / vite dev); .env.example en la raíz y en cada app; y un README.md en la raíz que explica cómo levantar el aplicativo en modo desarrollo. Sin lógica de negocio.

## Entregables

- package.json raíz con workspaces [apps/backend, apps/frontend] y scripts comunes (lint, test, typecheck)
- docker-compose.yml de desarrollo: postgres:16 (volumen persistente y healthcheck), mailpit (SMTP 1025, UI 8025), api (apps/backend/Dockerfile.dev, puerto 3000, depende de postgres healthy), web (apps/frontend/Dockerfile.dev, puerto 5173)
- apps/backend/Dockerfile.dev y apps/frontend/Dockerfile.dev con código montado como volumen, node_modules en volumen anónimo y recarga en caliente
- docker-compose.test o perfil 'test' con una base postgres de pruebas para los e2e
- Archivos .env.example (raíz, apps/backend, apps/frontend) con DATABASE_URL, JWT_ACCESS_SECRET, JWT_ACCESS_TTL, REFRESH_TTL_DAYS, VERIFICACION_TTL_HORAS, RESET_TTL_MINUTOS, FRONTEND_URL, MAIL_ADAPTER, SMTP_*, MAIL_FROM y VITE_API_BASE_URL
- README.md en la raíz: requisitos previos (Docker, Docker Compose, Node 20 opcional), cómo levantarlo (cp .env.example .env && docker compose up), puertos y URLs (web :5173, api :3000, Swagger /api/docs, mailpit :8025, postgres :5432), variables de entorno, cómo correr las pruebas dentro de los contenedores (docker compose exec api npm test / exec web npm test), cómo detenerlo y limpiarlo (docker compose down -v) y enlaces a apps/backend/README.md y apps/frontend/README.md
- Archivos .gitignore, .dockerignore, .editorconfig, configuración base de Prettier/ESLint compartida y la carpeta docs/adr/ con el ADR del estilo arquitectónico
