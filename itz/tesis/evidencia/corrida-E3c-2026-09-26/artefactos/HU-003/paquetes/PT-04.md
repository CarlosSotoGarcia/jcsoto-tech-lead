# PT-04 — Frontend: pantalla 'Restablecer contraseña' con estados del enlace

_HU-003: Recuperación de contraseña mediante enlace enviado por correo_

En /restablecer?token=, la pantalla consulta el estado del enlace. Si es vigente, muestra un formulario de nueva contraseña y confirmación con las reglas de la política compartida, y solo envía si las dos coinciden. Si el enlace está expirado, ya usado o no es válido, muestra el mensaje correspondiente con la opción de pedir uno nuevo. También traduce los errores del backend al enviar (TOKEN_EXPIRADO y TOKEN_USADO, que cubren el caso de los 59 y 61 minutos, y PASSWORD_POLITICA con la regla incumplida) y, si todo sale bien, redirige al login. Evita que el token se filtre a terceros con Referrer-Policy: no-referrer, tanto en una meta etiqueta como en una cabecera de nginx, y quita el token de la URL visible.

## Observaciones de la revisión

- **menor** (buenas_practicas) `apps/frontend/src/features/password-recovery/pages/RestablecerPage.tsx`: El placeholder anterior `RestablecerPage.tsx` sigue en el repositorio aunque el router ya no lo importa, como reconoce la propia descripción del PR. Es código muerto, y el README de frontend ya no lo menciona, así que la documentación y el código no coinciden.
- **menor** (pruebas) `apps/frontend/nginx.conf:22`: La cabecera `Referrer-Policy: no-referrer` solo llega a /restablecer si ninguna `location` del recorrido de fallback SPA (try_files → index.html) declara su propio `add_header`. En nginx, un `add_header` dentro de una location anula todas las cabeceras heredadas del server. El comentario da por hecho que esto se cumple, pero el README describe reglas de caché distintas para `/assets/` e `index.html`, y ninguna prueba verifica la cabecera. Las pruebas de Vitest solo comprueban la meta (TC-026).
- **menor** (buenas_practicas) `apps/frontend/src/features/login/pages/LoginPage.tsx:23`: El aviso 'PASSWORD_ACTUALIZADA' se lee de `location.state`, que el navegador conserva en la entrada del historial. Si el usuario recarga /login o vuelve a esa entrada más tarde, el aviso de contraseña actualizada aparece de nuevo aunque ya no venga del flujo de restablecimiento.
