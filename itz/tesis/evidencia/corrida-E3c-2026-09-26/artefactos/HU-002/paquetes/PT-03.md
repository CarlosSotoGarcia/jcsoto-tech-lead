# PT-03 — Frontend: pantalla de login con validación, mensajes de error y redirección por rol

_HU-002: Inicio y cierre de sesión con correo y contraseña, con redirección por rol_

Implementa la feature login. El formulario Iniciar sesión usa react-hook-form + zod: correo y contraseña obligatorios, formato de correo y campo contraseña de tipo password. Si la validación falla, la petición no se envía. Añade el hook useLoginMutation y el mapa de códigos de negocio a mensajes: genérico para credenciales inválidas, bloqueo temporal y cuenta no habilitada. AuthContext guarda el access token en memoria y la sesión se restaura con /auth/refresh al recargar. Tras el login redirige a la rutaInicial que devuelve el backend: /mis-vehiculos para CLIENTE y la pantalla 'Agenda del día' (placeholder InicioInternoPage) para el personal. Un usuario ya autenticado que entra a /login es enviado a su pantalla inicial. El cliente HTTP usa VITE_API_BASE_URL (HTTPS en producción) con credentials: 'include'.

## Observaciones de la revisión

- **menor** (pruebas) `apps/frontend/src/features/login/LoginPage.test.tsx:181`: La aserción `expect(ERRORES_LOGIN[codigo].status).toBe(403)` es tautológica: comprueba un dato del propio mock, no el comportamiento de la pantalla. No aporta verificación y puede dar una falsa sensación de que se cubre el código HTTP de TC-013/TC-014.
- **menor** (pruebas) `apps/frontend/src/features/login/LoginPage.test.tsx:192`: La prueba etiquetada como TC-017 simula un 400 del backend, pero TC-017 verifica que el propio backend rechace cuerpos vacíos o incompletos (APIRequestContext). Pasa lo mismo con TC-019/TC-021/TC-022/TC-023: dependen de la lógica del backend y no se validan con los mocks del frontend. Etiquetarlas así puede hacer creer que esos TCs quedan cubiertos por este paquete.
- **menor** (pruebas) `apps/frontend/src/auth/AuthContext.test.tsx:80`: La prueba de restauración espera '/interno' para un usuario RECEPCION, que coincide con la ruta de respaldo por rol. Así no distingue si AuthProvider guarda la `rutaInicial` que devuelve el refresh o solo usa la del rol. Tampoco se puede confirmar en el diff que el efecto de restauración pase por `iniciarSesion`.
